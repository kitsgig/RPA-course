# Робот категоризации товаров ДомТорг

Робот принимает файлы XLSX, CSV и XML, сверяет позиции со справочниками и передаёт нерешённые позиции GigaChat. Сотрудник проверяет отчёты в Excel. Следующий цикл записывает подтверждённые соответствия и готовит файл загрузки.

## Первый запуск в Windows

1. Откройте PowerShell в папке `domtorg`. Установите Python 3.11 или новее, затем выполните команды.

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. В проекте GigaChat API перевыпустите ключ, если он был опубликован в чате. Выполните команду под учётной записью Windows, которая будет запускать робота. В приглашении введите новый Authorization Key без префикса `Basic`. [Инструкция GigaChat API](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart)

   ```powershell
   .\.venv\Scripts\python.exe -m keyring -b keyring.backends.Windows.WinVaultKeyring set RPA-course GIGACHAT_CREDENTIALS
   ```

3. Подготовьте копию учебных файлов и запустите один цикл.

   ```powershell
   .\.venv\Scripts\python.exe demo.py
   .\.venv\Scripts\python.exe robot.py
   ```

   `demo.py` заполняет чистую папку обмена. В `config.toml` можно изменить пути, порог уверенности и параметры GigaChat. Параметр `--config` у обоих скриптов выбирает другую конфигурацию. Относительные пути отсчитываются от папки конфигурации. Параметр `ca_bundle_file` можно удалить, если доверенный сертификат уже установлен в Windows. [Справка по сертификатам](https://developers.sber.ru/docs/ru/gigachat/certificates)

## Проверка через веб-панель

Запустите панель из папки проекта.

~~~powershell
.\.venv\Scripts\python.exe .\web.py --config .\config.toml
~~~

Для установленной конфигурации подставьте `.\config.prod.toml`. Откройте в браузере [локальную панель](http://127.0.0.1:8765/) и выполните пробный цикл.

1. В разделе «Добавить файл» выберите поставщика и загрузите файл в формате его профиля. Файл появится в очереди.
2. Нажмите «Запустить цикл». Во вкладках «Файлы» и «Журнал» проверьте статус и итог обработки.
3. Скачайте «Отчёт XLSX», внесите решения в Excel и сохраните книгу. Загрузите её с типом «Проверенный отчёт» и запустите следующий цикл. Ссылка «Выгрузка XLSX» появится рядом с исходным файлом.

Панель использует те же папки, справочник и базу SQLite, что и ручной запуск. Она доступна на том же компьютере, пока запущен `web.py`. Для другого локального порта укажите `--port`, например `--port 8766`.

## Работа с позициями

1. Поместите новый файл в `Обмен/Входящие файлы/<поставщик>`. Для больших файлов сначала дождитесь полного копирования либо временно используйте имя с начальной точкой, затем переименуйте файл.
2. После цикла откройте файл из `Обмен/Отчёты`. На листе «Сведения» указаны поставщик, исходный файл, SHA-256 и версия справочников.
3. На листе «Категоризация» выберите решение для каждой обработанной позиции. Сохраните отчёт в `Обмен/Проверенные` и закройте его.

   | Решение | Действие |
   | --- | --- |
   | Принять | Подтверждает «Сопоставлено», «Предложено» или «Новый товар». |
   | Исправить | Укажите исправленный артикул каталога и положительный коэффициент. Остальные пустые поля робот заполнит по каталогу. Для новой карточки оставьте артикул пустым и укажите код конечной категории, название, единицу и коэффициент. При необходимости заполните исправленные характеристики. |
   | Отклонить | Закрывает позицию без выгрузки. |
   | Пустое решение | Оставляет позицию на проверке. |

4. После следующего цикла откройте файл в `Обмен/Загрузка`. Лист «Загрузка» содержит подтверждённые существующие позиции, лист «Новые товары» – подтверждённые заготовки новых карточек. Робот накапливает подтверждённые строки по исходному файлу в одной выгрузке.
5. Возьмите оставшиеся строки из обновлённого отчёта. Если исправление отклонено, причина находится в столбце «Комментарий робота». Исходники и обработанные проверенные отчёты перемещаются в `Обмен/Архив`. Повтор файла определяется по содержимому.

## Справочники и профили

В качестве образца используйте `samples/Справочники каталога.xlsx`. Меняйте справочники между циклами и закройте книгу перед проверкой отчётов. В книге должны сохраниться названия листов и порядок обязательных столбцов.

- **Категории.** Присвойте каждой строке собственный код. Для дочерней категории укажите код родителя. Максимальная глубина – три уровня. Обязательные характеристики перечислите через `;`.
- **Единицы.** Для каждой из шести внутренних единиц перечислите варианты поставщиков через `;`.
- **Правила.** Ключевые и исключающие слова и фразы перечислите через `;`. Правило срабатывает при наличии хотя бы одной ключевой фразы и отсутствии исключающих. Чем больше приоритет, тем раньше проверяется правило. Равноприоритетный конфликт разных категорий направляется сотруднику.
- **Каталог.** Каждой позиции нужен уникальный внутренний артикул, конечная категория и внутренняя единица. Характеристики укажите как `ключ=значение;ключ=значение`. Для артикулов и штрихкодов с ведущими нулями применяйте формат «Текстовый».
- **Соответствия.** Укажите поставщика, его артикул, артикул каталога и положительный коэффициент. Робот дополняет этот лист подтверждёнными решениями сотрудника.
- **Поставщики.** Имя поставщика должно совпадать с именем папки. Укажите один формат и привязки полей. Для XLSX задайте строку заголовков и при необходимости имя листа. Для CSV укажите строку заголовков, кодировку и разделитель, например `cp1251` и `;`. Для табуляции введите `\t`. Для XML задайте путь от корня к позиции, например `./items/item`, и имена дочерних элементов. Артикул и название обязательны. Если необязательного столбца или поля у поставщика нет, оставьте его привязку пустой.

## Уведомления и расписание

1. Для уведомлений заполните `[mail]` в `config.toml`. Укажите SMTP-сервер с TLS, порт, адрес учебного ящика в `sender` и адрес сотрудника в `recipient`. Если провайдер требует пароль приложения SMTP, создайте его в настройках безопасности учебного почтового ящика.
2. Сохраните пароль SMTP в хранилище Windows.

   ```powershell
   .\.venv\Scripts\python.exe -m keyring -b keyring.backends.Windows.WinVaultKeyring set RPA-course "адрес из sender"
   ```

3. Для ежедневных запусков с 09:00 до 18:00 по Иркутску включите компьютер в это время и настройте задачу Windows. Введите пароль той же учётной записи Windows в диалоге. Проверить задачу можно в «Библиотеке планировщика заданий» под именем `DomTorg catalog`. [Документация Windows](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/register-scheduledtask)

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\register-task.ps1
   ```

   Для просмотра XML без регистрации добавьте `-XmlOnly`. Изменив `interval_minutes`, обновите задачу в планировщике.

SQLite хранит статусы файлов, данные позиций и журнал за 30 дней. Если модель недоступна, робот всё равно формирует отчёт. Если почта не настроена или недоступна, итог доступен в консоли и журнале. Укажите рабочие пути и права доступа к файлам до включения расписания.

## Испытания

```powershell
.\.venv\Scripts\python.exe checks.py
.\.venv\Scripts\python.exe checks.py --live
.\.venv\Scripts\python.exe checks.py --live --performance
```

Второй и третий вызовы используют GigaChat и могут расходовать лимит API. Добавьте `--output .runtime\прогон-1`, чтобы сохранить отчёты и базу отдельного прогона. Результаты и методика приведены в [протоколе испытаний](TEST_PROTOCOL.md).
